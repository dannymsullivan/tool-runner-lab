# Support Agent Lab

A working support bot followed by four independent, self-paced Colab labs. Learn why Claude's Tool Runner exists, build the tools it calls, and check whether an action actually happened.

[Explore the website](https://dannymsullivan.github.io/tool-runner-lab/) · [Start Lab 1 in Colab](https://colab.research.google.com/github/dannymsullivan/tool-runner-lab/blob/main/tutorials/01-why-tool-runner.ipynb)

The GitHub Pages website replays recorded examples generated by real SDK, Python, and SQLite runs. It does not run a Python server or accept API keys. Choose **Open in Colab** to execute and edit a notebook, or run the full application locally as described below.

Start with the browser demo. Send the prepared customer request, inspect the saved return, then change the available stock and compare. **Explore the code** introduces the loop one cell at a time. **Lessons** opens the four labs directly.

Practice needs no API key. Model replies are scripted, while the Anthropic SDK, Python tools, and SQLite database really run. This makes experiments repeatable; it does not evaluate Claude's reasoning or prompt quality. Every bot run starts with a fresh store.

## Why this teaches Tool Runner

A model's tool request is only a request. Application code must execute it, return a result with the matching ID, preserve the conversation, and request the next model response. Tool Runner handles that recurring coordination. Your code still owns the tools, business rules, data access, and verification.

The first notebook runs a minimal manual loop before you replace it with the SDK runner. Later labs change the application without rewriting that loop. See the [Tool Runner guide](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-runner) and [manual tool handling](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls). The SDK is pinned because this interface is in beta.

This is an independent companion lab, not an official Anthropic course or assessment. The [tutorial design](TUTORIAL-DESIGN.md) records objectives, evidence, and remaining validation.

## Run the browser lab locally

Use Python 3.13. In this folder:

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py --host 127.0.0.1 --port 8765
```

Open [the lab](http://127.0.0.1:8765). Stop with Ctrl+C. Restart after changing Python; refresh after changing the UI. The standalone Colab notebooks do not require this server or repository.

## GitHub Codespaces

The source is in [dannymsullivan/tool-runner-lab](https://github.com/dannymsullivan/tool-runner-lab). The repository includes a Codespaces configuration; launching it in a hosted Codespace remains unverified.

1. Open the source repository, or use your own copy including `.devcontainer`.
2. Choose **Code → Codespaces → Create codespace**.
3. The container installs dependencies and starts the app. Open **Support Agent Lab** on port **8765** if needed.
4. Keep that forwarded port **Private**; live mode can use a key on its server.

Inside a Codespace, the source button opens that Codespace editor. Elsewhere, set `LAB_SOURCE_URL` to an HTTPS source URL without credentials. As a fallback, `GITHUB_REPOSITORY=owner/repo` links to a new Codespace for that repository. Without either, the button opens the general Codespaces page and explains that publishing is still needed.

If startup fails, inspect `/tmp/support-agent-lab.log`. After stopping the existing process, start manually with `python app.py --host 0.0.0.0 --port 8765`.

## Optional live Claude

The browser demo and the fourth notebook offer live Claude. A key is optional; live calls use API billing and the same fictional store. Live model decisions and wording can differ from scripted practice.

The notebook asks for a key privately with `getpass` after an explicit opt-in. Never put a key in a code cell. The browser keeps a supplied key in server session memory; disconnect when finished. For a developer-managed server, use `ANTHROPIC_API_KEY` and optionally `ANTHROPIC_MODEL`. `.env.example` documents these variables; the app does not automatically load `.env`.

## Source and verification

- `tutorial_runtime.py`: connects each learner function to the real bot and checks its behavior.
- `tutorial_series.py`: module metadata and notebook generator.
- `tutorials/`: eight standalone learner/reference notebooks.
- `lab.py`: reference tools, scripted responses, store, and outcome checks.
- `notebook_lab.py`: the browser's introductory cells and deeper experiments.
- `app.py` and `web/`: local server and interface, including notebook downloads.
- `tests/`: behavior, notebook execution, HTTP downloads, failure and isolation checks.
- `build_pages.py` and `docs/`: reproducible static export and the Pages publication folder.
- `publication.json`: GitHub repository and ref used for direct Colab links.

To update the Pages site after changing the code or notebooks, rebuild and commit `docs/` with the source:

```sh
python build_pages.py --repository dannymsullivan/tool-runner-lab --ref main --output docs
```

GitHub Pages publishes the `docs/` folder on `main`. The export runs and verifies both demo cases and all 15 code examples before saving recordings. It copies only the static assets and eight clean notebooks.

```sh
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

Tests execute the notebooks' embedded Python in clean namespaces with network access blocked, validate notebook structure, exercise actual widget callbacks, and verify that edited functions change bot behavior. These are local checks; hosted Colab rendering, live API calls, and a human learner rehearsal remain to be validated.

The original `tool-runner-lab.ipynb` remains as a full worked reference. The older `exercises/` files and checks also remain for additional practice; unlike the new Colab exercises, they are separate from the browser simulation. Check them with `python exercises/check.py --exercise inventory` or `--exercise runner`; add `--reference` to check a supplied answer without overwriting your work.
